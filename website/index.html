02 — How to read the archive

A snapshot has
edges.

The archive is useful for finding and examining old work. It is not a promise that every project builds, runs or remains supported.

A

Start with its README

Each folder is independent. Read its setup and status notes before installing dependencies, opening a device image or treating a prototype claim as a verified result.

B

Trace the source pin

IMPORTS.md pairs a project folder with its source branch and commit. The archive commit is the published snapshot; the source history is elsewhere, if still available.

C

Check notices locally

There is no root license that overrides a project. Review its own LICENSE, notices and README before reuse. Some folders may not include a top-level license file.

D

Expect different toolchains

The collection ranges from Python exercises to Android, Rust, GTK, browser demos and HDL research. There is no root dependency set or common build/test command.

03 — Beginner walkthrough

Your first result:
13.0

Try the small Python calculator in SCCM4910labs. This walkthrough reads one project in place; it does not install dependencies or change the archive.

  1. 01

    Check the project notes

    Open SCCM4910labs and read README.md and REQUIREMENTS.md. It is a Python 3 command-line exercise.

  2. 02

    Use Python 3

    From the Legacy repository root, check that Python is available: 

    python3 --version
  3. 03

    Start the calculator

    Run the included program:

    python3 projects/SCCM4910labs/calculator.py
  4. 04

    Enter two numbers and an operator

    At the prompts, type 8, then +, then 5. The verified output is Result: 13.0. The calculator then prompts for another calculation.

NOTE

This snapshot has no quit command. Press Ctrl + C to stop it; Python prints a KeyboardInterrupt traceback. Division by zero and non-numeric input are also not handled by this small exercise.

04 — Technical notes

What each snapshot includes.

A compact reference for contributors, researchers and anyone deciding whether to build from a snapshot.

What is pinned?

Each folder in projects/ captures one listed source branch at one full commit SHA. The import manifest says snapshots were imported on 26 October 2026. It does not include upstream Git history.

What is not shared?

Dependencies, build systems, supported platforms, test commands and licenses vary by project. There is no top-level package manager or universal test suite. Follow only the selected folder’s own instructions.

Security and handling

Research and hardware folders have project-specific limits. The GM2 Pro notes explicitly exclude vendor firmware dumps and device-unique data. SecureeEar documents residual native-library risk. Check each project’s own threat and handling notes.

MaterialPipe publication note

PUBLIC_ARCHIVE_NOTES.md says two credential-like constants were replaced by placeholders during publication review. Features depending on them may need project-specific configuration.

Root documentation

README is the catalog, IMPORTS.md is the provenance index, and LICENSES.md explains the per-project licensing model.

Building safely

Inspect scripts before running them. Prefer a disposable, project-specific environment for unfamiliar toolchains. Treat Android images, firmware tools and HDL claims according to the instructions and limitations in their own folders.

A few useful answers

Before you dive in.

Can I build every project with one command?

No. This is an archive of independent snapshots using different languages and toolchains. Choose a folder and follow its own README and requirements.

Does this archive include original Git history?

No. IMPORTS.md records the source branch and commit for each snapshot, but the original histories are not included in Legacy.

Can I reuse code from any folder?

Check that project’s own license and notices first. LICENSES.md states that no single root license overrides the terms included with each project; some folders may have no top-level license file.

Are the listed projects maintained?

This repository is explicitly an archive of older and experimental work. Treat status claims as a snapshot and visit a source repository, if available, for current maintenance information.
